# Design
Extract WriteRawFileDto(DataBase64) and CopyRawFileDto(SourceIndexId, SourceFileId). Use WriteRawFileResultDto and CopyRawFileResultDto instead of the shared nested response. Write results retain nullable source IDs so their existing JSON fields are preserved; copy results use the always-present source IDs. Map results at each handler and keep the current cache raw-write/copy operations, validation and invalidation ownership unchanged. Verification only writes isolated MemoryFileStore instances.

## Verification
Service/test projects built through dotnet test and all 101 service tests passed. WriteAndCopyDtos_RetainResultFieldsAndExactBytes verifies both result DTOs, null source fields on writes, populated source IDs on copies and exact destination/source bytes. WriteDto_InvalidBase64DoesNotChangeDestination and CopyDto_InvalidSourceDoesNotChangeDestination cover rejected payloads. Existing raw-store mutation coherence and negative destination ID tests pass with the new request DTOs. Strict OpenSpec validation and git diff --check passed. No new source compiler warnings; existing NuGet warnings remain. All mutations used isolated MemoryFileStore instances; no live cache mutation or service restart occurred.
