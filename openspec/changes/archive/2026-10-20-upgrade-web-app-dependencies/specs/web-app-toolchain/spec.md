## ADDED Requirements

### Requirement: The web app uses one supported Angular dependency major

The `Hagalaz.Web.App` package manifest and resolved dependency graph MUST keep the Angular framework, compiler, CLI/build, Material/CDK, router, platform, and service-worker packages on one compatible major release supported by the selected Node and TypeScript versions.

#### Scenario: Angular packages are upgraded together

- **WHEN** the dependency upgrade is applied
- **THEN** the direct Angular packages and their lockfile resolutions use one compatible current Angular major without mixed-major peer dependencies

#### Scenario: Angular compatibility constrains toolchain versions

- **WHEN** the newest registry version of TypeScript or Node-dependent tooling falls outside the selected Angular release's supported range
- **THEN** the project uses the newest compatible version and records the constrained package rather than accepting an incompatible graph

### Requirement: The dependency graph is reproducible

The project MUST declare the upgraded direct dependencies in `package.json` and commit a lockfile generated by the pinned pnpm package manager, with no second package manager or competing lockfile introduced.

#### Scenario: A clean install resolves the declared graph

- **WHEN** dependencies are installed from `Hagalaz.Web.App` using the declared pnpm package-manager version and frozen lockfile
- **THEN** installation succeeds and resolves the same direct dependency versions recorded in `pnpm-lock.yaml`

### Requirement: Existing frontend targets remain verifiable

The upgraded toolchain MUST continue to support the existing web, admin, unit-test, lint, and Electron launcher build targets, or any incompatibility MUST be explicitly reported as a follow-up.

#### Scenario: Web checks pass after upgrade

- **WHEN** the existing web build, unit test, and lint scripts run after installation
- **THEN** they complete successfully without changing application feature behavior

#### Scenario: Launcher and admin targets use the upgraded graph

- **WHEN** the existing admin and Electron launcher validation commands run after installation
- **THEN** they resolve the upgraded dependency graph and either complete successfully or produce a documented environment/upstream compatibility limitation
